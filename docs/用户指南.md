## 它能做什么

- **语义化生成**：结合字段名、**中文注释**、数据类型，生成贴近业务的真实数据——中文姓名、18 位身份证、银行卡号、合理金额、YYYYMMDD 日期、状态码枚举等（Faker `zh_CN` 本地化）。
- **多表逻辑闭环**：即使通过不同字段名（如 `cust_no` 与 `party_id`）、不同中间表关联到同一实体，关联查询也能命中且结果一致。
- **表关系图谱**：AI / 启发式自动识别表关系，支持导入 / 导出 Cypher，图可视化 + 表格编辑。
- **三种自定义规则**：① 自然语言描述（AI 翻译）② 样例数据（INSERT SQL / CSV）统计识别 ③ 手动编辑。
- **内嵌数据库**：DuckDB 存储生成结果（SQL Explorer），可选 Kuzu 图库（Cypher Explorer），开箱即用。
- **多格式导出 / 写库**：CSV / JSON / SQL / Excel / Cypher，或直接写入外部 MySQL。

## 快速开始

### 环境要求

- Python ≥ 3.11（推荐使用 [uv](https://github.com/astral-sh/uv)）
- Node.js（构建前端）

### 启动（Windows 一键脚本）

```powershell
.\scripts\start.ps1          # 构建前端 + 启动后端
# 开发模式：.\scripts\start-dev.ps1
```

启动后访问 **http://localhost:8000**。

### 手动启动

```bash
# 后端
cd backend
uv sync                       # 安装依赖（需要图库时：uv sync --extra graph）
uvicorn main:app --port 8000

# 前端（另开终端）
cd frontend
npm install
npm run build                 # 产物输出到 frontend/dist，由后端托管
# 或开发模式：npm run dev
```

## 操作流程

界面顶部为功能标签页，典型使用流程如下：

### 1. 解析 Schema（Schema 标签）

- 粘贴或导入 SQL DDL（支持多文件，会自动拼接解析）。
- 选择方言（MySQL / PostgreSQL / SQLite / Doris 等）。
- 点击解析，生成内部 Schema。

### 2. 配置表关系（表关系图谱 标签）

保证多表关联一致的关键步骤。

- **AI 识别关系**：根据字段名与中文注释自动推断表间关系（含跨字段名的同义关系）。未配置 AI 时自动回退到启发式。
- **导入 Cypher**：粘贴或上传关系图文件（如 `test_ddl/schema_graph.cypher`），即作为表关系导入。
- 在**关系图**与**表格**中查看、编辑（增删改子表/父表/字段），点保存。
- 可**导出 Cypher** 留存关系定义。

> 关系表示"子表字段引用父表字段"。父表是主表/权威表（如客户主表），生成时其值先生成，子表从中采样，从而保证 JOIN 闭环。

### 3. 自定义字段规则（自定义规则 标签，可选）

三种方式，优先级高于自动推断：

- **自然语言**：输入如"年龄在 18 到 60 之间；手机号 138 开头；状态只能是 正常/冻结/销户；金额保留两位小数最大五万"，点「AI 解析规则」。
- **从样例数据识别**：粘贴 INSERT SQL 或上传 CSV，自动统计推断每列规则（数值范围、小数位、日期范围、枚举、定长模式等），**无需 AI**。
- **手动添加**：直接选择列、规则类型并填参数。

编辑完点保存，规则随 Schema 持久化。

### 4. 生成数据（Generate 标签）

- 为每张表设置生成行数。
- 点击生成（可开启**流式模式**查看实时进度）。
- ⚠️ 生成为**覆盖式**：每次会清空重建后写入，不追加。

### 5. 查看与验证

- **数据预览**：表格化浏览生成结果。
- **SQL Explorer**：对 DuckDB 执行只读 SQL（如用 `JOIN` 验证关联）。
- **Cypher Explorer**：查询图数据（若使用图 Schema）。

### 6. 导出 / 写库

- **导出 标签**：选择 CSV / JSON / SQL / Excel 下载。
- **MySQL 配置 / 写入 标签**：配置外部 MySQL 连接并将数据写入。

## 可选配置（AI / MySQL）

### AI（OpenAI 兼容）

在 **AI 配置** 标签填写 `base_url` / `api_key` / `model` 并测试连通性。支持 OpenAI、DeepSeek、Ollama、OpenRouter 等任意 OpenAI 兼容服务。

也可通过环境变量（前缀 `DATAFORGE_`，或 `backend/.env`）配置：

```
DATAFORGE_LLM_BASE_URL=https://api.openai.com/v1
DATAFORGE_LLM_API_KEY=sk-...
DATAFORGE_LLM_MODEL=gpt-4o
```

> AI 为**可选增强**。自然语言→规则、AI 关系/字段推断需要 AI；**样例数据识别与语义生成不需要 AI**，未配置时自动降级到规则生成。

### MySQL 写入

在 **MySQL 配置** 标签填写主机、端口、库名、账号密码，测试连接后即可在 **MySQL 写入** 标签把生成数据写入真实库。

## 命令行端到端脚本

`backend/run_e2e_test.py` 会合并 `test_ddl/` 下所有 DDL、注入 `schema_graph.cypher` 关系、生成数据、校验 JOIN 闭环，并把 CSV 导出到 `output/`：

```bash
cd backend
.venv/Scripts/python run_e2e_test.py          # 纯规则生成
.venv/Scripts/python run_e2e_test.py --ai     # 启用 AI 种子增强
```

## 导出格式

| 格式 | 说明 |
|------|------|
| **CSV** | 每表一个 CSV，打包为 ZIP |
| **JSON** | 各表数据的 JSON |
| **SQL** | `INSERT` 语句 |
| **Excel** | 多 Sheet 工作簿（.xlsx） |
| **Cypher** | 表关系图（从「表关系图谱」导出） |

## 常见问题

**Q：生成的数据是覆盖还是追加？**
A：覆盖。每次生成都会清空相关表后重新写入，不在原数据上累加。

**Q：为什么字段是随机字符串，不够真实？**
A：语义生成依赖字段的中文注释/字段名。请确认 DDL 含 `COMMENT`；也可在「自定义规则」中用自然语言、样例数据或手动方式指定更精确的规则。

**Q：多表 JOIN 查不到数据 / 关联不上？**
A：请先在「表关系图谱」中识别或导入正确的表关系并保存。关系定义正确后，生成的数据会保证关联闭环。

**Q：端口 8000 被占用 / 启动失败？**
A：先结束占用进程（Windows：`Stop-Process -Id <PID> -Force`），或用 `scripts/start.ps1 -Port 8001` 换端口。

**Q：集成测试报 `ConnectError`？**
A：集成测试需要先启动后端服务（连 `localhost:8000`），这是环境问题而非代码缺陷。
